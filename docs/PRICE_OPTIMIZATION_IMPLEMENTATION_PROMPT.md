# 판매가·마진 최적화 센터 구현 프롬프트

## 역할
너는 AutoSellerAI의 수석 커머스 자동화 아키텍트다. 위탁판매 상품의 도매 공급가와 쿠팡/네이버 스마트스토어의 실제 판매가를 비교하고, 사용자가 승인한 상품만 안전하게 가격 수정하는 운영 시스템을 구현한다.

## 핵심 목표
1. 도매가(공급가), 쿠팡 현재 판매가, 스마트스토어 현재 판매가를 같은 상품 기준으로 비교한다.
2. 목표 순마진율 기본값은 36%이며, 판매가 기준 공식은 아래를 사용한다.
   - 권장판매가 = 공급가 / (1 - 플랫폼수수료율 - 목표마진율)
3. 플랫폼 수수료는 상품별/카테고리별로 결정한다.
   - 최근 실제 주문의 platform_fee_rate가 있으면 우선 사용
   - 사용자가 저장한 플랫폼+카테고리 수수료 규칙이 있으면 다음 우선순위
   - 없으면 화면에서 지정한 플랫폼 fallback 수수료를 사용하고 '추정'으로 표시
4. 가격 끝자리 정책(900/500/100/10원)을 적용하되 목표마진 아래로 내려가지 않도록 항상 올림한다.
5. 현재가, 현재 예상마진, 권장가, 변경액, 도매가 출처, 수수료 출처를 표로 보여준다.
6. 한 상품, 선택 상품, 전체 적격 상품을 각각 수정할 수 있어야 한다.
7. 가격 변경 전 반드시 미리보기와 사용자 승인 체크를 요구한다.
8. 가격 수정 실패는 상품별로 격리하며 다른 상품 처리를 중단하지 않는다.
9. 모든 가격 변경을 before/after, 수수료율, 목표마진, 도매가와 함께 감사 로그로 저장한다.
10. 공급가가 없거나 0원인 상품, 판매가가 0원인 상품, 수수료가 비정상인 상품은 자동 적용하지 않는다.

## 도매가 결정
- Product.supply_price > 0 이면 1순위
- SupplierRawProduct/SupplierWorkflowItem에서 product_id 직접 연결된 공급가가 있으면 사용
- 마켓 import 상품의 경우 정규화된 상품명이 완전히 같은 공급가 보유 Product가 유일할 때만 exact-name 후보로 사용
- exact-name 후보는 UI에서 출처를 명확히 보여준다.
- 애매한 fuzzy match는 가격 자동변경에 사용하지 않는다.

## 쿠팡/네이버
- 마켓 현재가는 공개 판매자 API에서 새로 읽을 수 있어야 한다.
- 네이버는 원상품 salePrice 수정 API를 사용한다.
- 쿠팡은 seller product 상세를 재조회한 후 item별 salePrice만 변경하고 다른 필드는 보존한다.
- 외부 API 변경은 동일 요청에서 중복 호출하지 않는다.

## 쿠팡 자동판매가 정책
- 기준 판매가 대비 하락/상승 허용률(-X%, +Y%)을 정책으로 저장한다.
- 하한은 목표마진 보호가격보다 낮아질 수 없다.
- 공개 API에서 Wing 자동가격조정 설정 자체를 검증하지 못한 경우, 이를 'AutoSellerAI 가격 가드 범위'로 명확히 표시하고 플랫폼 기능을 설정했다고 주장하지 않는다.

## 안전성
- SQLite write는 짧은 트랜잭션과 기존 retry_sqlite_write 경로를 사용한다.
- 원격 가격 수정 후 로컬 로그 저장이 잠겨도 원격 API를 재호출하지 않는다.
- 실패 상품은 오류를 기록하고 나머지는 계속 처리한다.
- 수수료 fallback은 공식 카테고리 수수료라고 표시하지 않는다.
